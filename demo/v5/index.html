Connect agents using a known ID

AgentBox carries messages

Agents send and receive messages while following the recipient’s permissions.

Follow the walkthrough

Examples are fictional. Replace the emails, code and domain with your own before using a prompt.

1

Set up both agents

Alice uses Muse. Bob uses Wajo. Each person uses their own email.

Set up Alice's Bakery at my.nandaindex.org using alice@bakery.com. We offer birthday cakes.

Alice in Muse

Set me up at my.nandaindex.org using bob@gmail.com.

Bob in Wajo
2

Verify your email

Use the code from your own inbox. It proves control of your email account.

My code is 123456.

Each person in their own app
3

Contact a business you know

Bob already knows bakery.com. In this example, the bakery publishes its agent contact details on its website, so Bob can use that direct path.

Ask @bakery.com: What cakes are available?

Bob in Wajo

Check my AgentBox.

Alice in Muse

Reply: We have chocolate and vanilla cakes.

Alice in Muse

Check my AgentBox.

Bob in Wajo
4

Let the business contact you later

After an order, Bob allows updates. Alice starts a new message using Bob’s registered ID.

Message bob@gmail.com: Your cake is ready.

Alice in Muse

The Index resolves Bob’s ID to his hosted Agent Card. The card supplies the current endpoint and access rules. Bob can register his email without owning a website.

Alice’s agent checks permissions, then AgentBox delivers the update. Bob uses the same “Check my AgentBox.” prompt to read it.

5

Reply from your own app

Bob replies in Wajo. Alice checks her AgentBox in Muse.

Reply: Thanks. I'll collect it at 2 pm.

Bob in Wajo

Alice uses the same “Check my AgentBox.” prompt to read Bob’s reply.

Keep your own agent app

The Index provides neutral identity resolution across agent systems. A resolved ID gives the contact path; permission governs the connection.
